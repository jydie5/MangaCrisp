## 最終候補の共通読書・本棚挙動

挙動はすべてOS非依存の`src/mangacrisp_app/`にあります。OSごとの読書画面を複製しません。

- 読書画面には**常設の下部ツールバーを置きません**。`P`は設定サイドバーだけを表示／非表示
  にします。
- 画面中央の読書領域をクリックすると、半透明の**読書コントロール**ペインを表示します。
  前／次の見開き、1ページ戻る／進む、原画／補正版比較、設定、全画面、レイアウト、ヘルプ、
  （有効時の）しおり、本棚への復帰をここから操作できます。中央操作を行うまでペインは隠れています。
- ペインの外のページ領域をクリックするとペインを閉じ、そのクリックを消費するためページ送りは
  起きません。ペイン内の空白左クリックも閉じますが、ペイン内のボタン操作はそのまま実行します。
- `H`または`?`でモーダルの操作一覧を開きます。`Esc`またはペイン外の押下・離上で閉じます。
  モーダルが終了クリックを消費するため、下のページや本棚へクリックが漏れません。
- 読書画面の`Esc`は、読書コントロールを先に閉じ、次に全画面を解除し、最後に本棚へ戻ります。
  操作一覧を`Esc`／背景クリックで閉じても、全画面状態やページ位置は変わりません。読書コントロールは
  全画面中も利用でき、埋め込み読書画面でも残ります。
- ショートカットは、表示中でモーダル／ポップアップがなく、イベント対象が読書画面内の場合だけ処理します。
  行編集・スピンボックス・コンボボックスの矢印や入力は各コントロールへ渡し、`Esc`だけは入力欄からも
  読書画面の脱出として扱います。ボタンにフォーカスがあるときのSpace／Returnはボタンを実行し、
  ページ送りにはしません。Ctrl／Command／Alt付きの組み合わせは各コントロールまたはOSへ渡します。
- 本棚の共通挙動は維持します。複数選択、読む／本棚から削除の右クリックメニュー、1回の確認でのまとめ削除、
  元アーカイブの保持、管理コピー削除失敗時の登録維持と通知を使います。
- 全画面のカーソル自動非表示も共通です。画像上で2秒操作がなければ隠し、操作やフォーカス復帰で表示します。
  コントロール、オーバーレイ、ポップアップ、ダイアログ、ドラッグ中、非アクティブ／終了中は隠しません。

読書コントロールのチェックポイントは次のとおりです。

| チェックポイント | 範囲 |
|---|---|
| `5320092` | 最初の読書コントロールと中央の半透明ペイン |
| `8fd3c81` | 必要時だけ表示、常設下部ツールバーの削除、本棚の更新 |
| `97dc06f` | 操作一覧モーダル、`Esc`、背景クリック、フォーカス処理 |

## 補正・キャッシュ基盤

PR #53（`78c2cc6`、実装チェックポイント`1c1a8a6`）は読書操作候補と一緒に維持します。

- `models-pro`はReal-CUGANへ正確なタイル同期の`-c 1`を常に渡します。パラメータキーにも
  `_syncgap1`を含め、例は`scale3_noise3_tile0_models-pro_syncgap1`です。旧形式のpro結果を
  同じ設定として再利用しません。
- Real-CUGANは出力ディレクトリ内の一時PNGへ書きます。終了コード0、期待サイズ、PNG検証、
  2回目の`load()`をすべて通った場合だけ原子的に置き換えます。失敗、中断、破損、サイズ不一致では、
  既存の正常なキャッシュを残し、部分出力をキャッシュヒットにしません。
- `CorrectionDiskCache`が補正パスとセッション中のtouch状態を管理します。通常画像は従来のパス／サイズ／
  mtime由来キーを使い、遅延プロバイダは`cache_source_identity(index)`だけを使って画像を実体化せずにキーを作ります。
  PDFページの識別子はPDFソースキー、DPI、ページ番号を含むため、再起動や描画PNGのtouchではAIキャッシュの
  識別子が変わりません。PDF本体が変わった場合は意図的に別識別子になります。
- AI補正PNGは共通pruneで**2 GiB**、**30日**に制限します。処理中の出力、その親ディレクトリ、
  stagingの子孫を保護します。読書中は保護範囲外の`processed_pages`参照だけを解放し、完了したディスク結果は
  LRU／経過時間の整理に任せるため、前後移動のたびに即再処理しません。
- キャッシュ済み出力のtouchは読書セッションごとに最大1回で、lookupだけで消えたファイルを再作成しません。
  本を削除すると、そのソースに対応する補正フォルダを削除します。遅延プロバイダの削除でもページ画像を描画しません。
  PDF描画PNGも2 GiB／30日の有界キャッシュで、最近のページだけをメモリに保持します。
- 表示デコード中は表示中の左右とフォールバックを保護します。遅れて終わった予熱デコードが表示中の片側を追い出し、
  補正版から原画へ瞬いて戻ることを防ぎます。

## ネイティブ受け入れの範囲を限定したチェックリスト

最新の`main`から開始し、再配布可能なdemo素材を使います。クロスビルドはしません。

### Windows

Windows上で`scripts/build_windows_app.py`と`scripts/package_windows_portable.py`を使います。

1. デモ本を開き、中央クリックで操作ペイン、外側のページクリックでページを送らずに閉じること、
   `H`／`?`の操作一覧、操作一覧の`Esc`／背景クリックを確認します。後者で全画面とページ位置を変えません。
2. 常設下部ツールバーがないこと、`P`が設定サイドバーだけを切り替えることを確認します。手動設定の
   spin box／comboの矢印でページが動かず、入力欄からの`Esc`で操作ペインを閉じることを確認します。
3. 全画面中も操作ペインが使え、カーソルが仕様どおり隠れて戻ることを確認します。配布版が両方を公開する場合は、
   standaloneと埋め込み読書画面を別々に確認します。
4. `models-pro`で実行引数と結果キーに`_syncgap1`があることを確認します。失敗／不正出力が既存PNGを置き換えず、
   先読み完了後に補正版が原画へ瞬いて戻らないことを確認します。
5. 補正付きの本を1冊、複数選択をまとめて削除します。確認が1回で、元アーカイブが残り、管理コピーとページ補正
   キャッシュが消えること、ロックされた本は登録を維持し他の削除は成功することを確認します。
6. `uv run pytest -q`とWindows配布版のスモーク確認を実行し、GPUやクリーンアカウントの未確認点を記録してから
   Windows候補を公開します。

### Linux

Ubuntu 24.04以降で`scripts/build_linux_app.py`を使います。

1. 上記の読書操作、操作一覧、フォーカス、全画面、`models-pro`、原子的出力、ちらつきなし、削除を確認します。
2. GNOME WaylandとX11でカーソル自動非表示を別々に確認し、右クリック位置、Ctrl／Shift選択、portal／キャプチャを確認します。
3. Linuxのapp-support配下でキャッシュパスを確認し、処理中の出力とstagingの子孫がpruneで残ることを確認します。
4. Linuxキャプチャテストを含めて`uv run pytest -q`を実行し、compositor、GPU、倍率の未確認点を記録します。
   共通読書画面へLinux分岐を追加しません。

Windows b0.4とLinux b0.3の合格記録は、それぞれの過去のrelease文書に残っています。これは旧previewの
プラットフォーム証跡であり、今回の最終読書操作候補のネイティブ合格を代用しません。

## ロールバックと競合境界

- PR #53／`1c1a8a6`（`78c2cc6`としてマージ済み）を残したまま、読書UIだけを調査・ロールバックします。
  UIチェックポイントを新しい順に`ed7fa11`、`97dc06f`、`8fd3c81`、`5320092`の順でrevertすれば、補正・キャッシュ修正を維持したまま
  読書UIだけを戻せます。これはソースとUIだけを変え、利用者の本、設定、キャッシュを削除しません。
- `viewer.py`、`bookshelf.py`、`page_provider.py`、`cache_utils.py`、補正モジュールを編集する前に最新`main`へrebaseします。
  共通の補正／キャッシュ修正と各OSのpackaging変更を両方残してください。
- OS固有のキャプチャ、packaging、署名、release作業は`platform/`または`packaging/`に置きます。Windows／Linuxの回避策を
  共通readerへコピーしません。詳細は[共通workflow](cross-platform-workflow.md)、[Windows引き継ぎ](windows-handover.md)、
  [Linux引き継ぎ](linux-handover.ja.md)を参照してください。
- 各OSのダウンロード案内は、この候補を含むネイティブ検証済みパッケージを実際に公開してから更新します。
