現行Linux previewと今後のネイティブ検証は、このチェックポイントを使用します。現行の共通ソースには
PR #53/#54までの読書画面、本棚、補正、キャッシュの変更が入っています。UIのリリース系統は
[35f2936](https://github.com/jydie5/MangaCrisp/commit/35f2936)、配布物のソースチェックポイントは
[d7bbf50](https://github.com/jydie5/MangaCrisp/commit/d7bbf50)です。
現行Linux Development Previewは、`d7bbf50`の`main`から作成した
[linux-preview-0.7.1b0.4](../releases/linux-preview-0.7.1b0.4.md)です。ネイティブCIは
[39335510308](https://github.com/jydie5/MangaCrisp/actions/runs/39335510308)、アーカイブのSHA-256は
`5b48794d7b75b6edd9be34c7aeea09eaecb7a5319fe0f41ddcc874c08d503ed7`です。以前のb0.3は現行の読書コントロール、
ショートカットヘルプのモーダル、補正／キャッシュライフサイクルより前の版で、上書きしない履歴・ロールバック用成果物です。
リリース文書はクリーンなdemoギャラリーと[撮影手順](../images/README.md)を参照します。

macOS実機でUI操作を確認済みです。macOSの自動テストは**274成功、8スキップ、12サブテスト成功**でした。
b0.4のソースと配布版起動確認はリリース文書に記録しています。2026-10-20に利用者から、この現行UIが
実Linux機で動作したとの一般的なネイティブ成功報告を受けました。Linuxのセッション、GPU／ドライバ、倍率、
配布版スモーク、個別チェック項目の証跡は含まれていないため、証跡がない詳細ゲートは保留です。クロスプラットフォームの背景は
[共通UX引継ぎ](ux-maintenance-handover.ja.md)を参照し、この文書にはLinuxの合否と
環境記録を残します。

Linuxで確認する現行動作:

- 読書画面に下部ツールバーを常時表示しません。画面中央をクリックすると半透明の
  読書コントロールペインを開きます。ペインの背景をクリックするとページを送らずに閉じます。
- Hまたは?でショートカットの操作一覧モーダルを開きます。半透明の背景が外側クリックを
  受け止め、閉じるボタン、Esc、カード外側のクリックで閉じます。閉じるためのクリックが
  読書画面へ届いてはいけません。初期フォーカスは閉じるボタンで、閉じた後は読書画面へ戻します。
- 本棚はスコープを限定した濃紺／ティール配色で、冊数、選択状態、主操作の「読む」、
  副操作のファイル／フォルダ／キャプチャを分かりやすくします。既存の取り込み、
  コンテキストメニュー、複数選択、削除動作もネイティブ確認の対象です。

確認する補正とキャッシュ動作:

- models-proは明示的に-c 1（syncgap 1）で実行し、パラメータキーは_syncgap1を含みます。
  古いmodels-proキャッシュキーを再利用せず、SEのキーは互換のままです。
- CorrectionQueueは表示中／現在ページを先読みより優先し、実行中の出力を1件保護します。
  完了時には重複作業を除去し、世代／設定変更、終了、ページ移動で古い完了通知を無効化します。
  補正エラー後は静止中に無限再試行せず、移動または設定変更で再試行します。
- CorrectionDiskCacheとDisplayCacheは戻る操作で完成済み出力を再利用します。消えたprocessed
  パスは再キューします。サイズ／保存期間の整理では表示中、待機中、実行中、staging親を保護し、
  外部のprocessed原本を削除しません。先読み完了時に補正版→原画→補正版とちらつかないことも確認します。

X11とWaylandを別々に、小数倍率も含めて実行し、Ubuntu／デスクトップ／Qtの版、GPU／ドライバ、

1. 中央クリックの操作ペイン、下部ツールバー非表示、半透明モーダル、外側クリック、
   Esc、初期フォーカス、閉じた後のフォーカス復帰を確認します。
2. 補正を有効にして前後へ移動し、離れたページへ戻り、原画／補正版を比較します。
   表示中優先、補正エラー後の再試行、古い完了通知の取消、ちらつきなしを確認します。
3. models-proを実行し、-c 1が_syncgap1へ書き込み、古いproキー画像を無視し、SE出力を再利用し、
   消えたprocessedを再生成することを確認します。実行中／staging出力は整理から保護し、
   元アーカイブを変更しないことも確認します。
4. おおむね900x620と小数倍率で本棚を確認します。冊数、選択状態、主操作の「読む」、
   取り込み／キャプチャ、複数選択、右クリック対象、管理コピー削除が使えることを確認します。
5. 全suiteとネイティブ配布版スモークテストを実行し、Linuxのスキップ数とサブテストを
   macOSの合格結果とは別に記録します。

previewのCI確認では、上記の環境ごとの証跡までは得られません。これらは一般的なネイティブ成功報告があっても

## UI/UX候補のLinux実機確認（d7bbf50、2026-10-21）

ソースは`main`の`d7bbf50`（PR #53/#54、UIチェックポイント`97dc06f`・`ed7fa11`を含む）。
配布物はUbuntu 24.04 CIの成果物
（[run 39335510308](https://github.com/jydie5/MangaCrisp/actions/runs/39335510308)）で、
`SHA256SUMS.txt`と照合済み。

Linuxでの自動確認:

- `uv run pytest -q`: **274成功、8スキップ、12サブテスト成功**。スキップ8件はすべて
  macOS／Windows専用テスト。XvfbでのX11キャプチャテストは実行・合格。
- `scripts/build_linux_app.py`のネイティブビルドと配布版スモークテストが合格。
- `packaging/linux/validate-clean-ubuntu.sh`がクリーンなUbuntu 24.04／26.04で合格
  （インストール、スモーク、デモ本、7-ZipのRAR、CPU VulkanでのReal-CUGAN、アンインストール）。
- GTX 1060で`models-pro`を`-c 1`付きで実行し、終了コード0で出力を確認。キャッシュは
  `~/.cache/MangaCrisp/{upscale,pdf-render}`に作成。

実機確認: インストールしたCI配布物を、Ubuntu 26.04.1、GNOME 50.1、Wayland、Qt 6.11.1、
4K・125%の小数倍率、NVIDIA GeForce GTX 1060 6GB（ドライバ580.178.04）で起動。
読書操作ペイン、操作一覧モーダル、全画面とカーソル、補正のちらつき、本棚の表示、
複数選択、削除、再開位置の確認項目を利用者に渡し、「確認終わり」との報告を受領。
候補全体の合格であり、各項目の個別報告ではない。

ここで未確認の項目:

- 実デスクトップのX11: Ubuntu 26.04／GNOME 50にはXorgセッションがない。X11は
  Xvfbでのキャプチャ／ショートカット自動テストのみ。
- AMD／Intel GPU。

後続の`linux/`修正候補: 24.04でビルドした配布物が古いGLibを同梱するため、26.04では
システムのgvfs GIOモジュールの読み込みに失敗する
（`libgvfscommon.so: undefined symbol: g_variant_builder_init_static`）。閲覧、取り込み、
キャプチャへの影響は見られない。GLib／GIOを同梱しない、またはフリーズ版で外部GIO
モジュールを無効にする方法が考えられる。

公開中のLinux版はpreview b0.3のまま。この候補で新しいLinux previewを公開するには、
利用者からのリリース指示が必要。

## 最初に行うこと

`AGENTS.md`、[並行開発ルール](cross-platform-workflow.md)、
[共通UX引継ぎ](ux-maintenance-handover.ja.md)、
[Linux導入手順](../../INSTALL.linux.ja.md)、
[Linuxパッケージ手順](../../packaging/linux/README.md)を読んでください。
[移植計画](linux-port-plan.ja.md)の古いテスト数や配布方式案より、この引継ぎを優先します。

まず`git status --short --branch`で未コミット変更を確認し、残っていれば保全します。
作業ツリーがきれいになってから、共通修正のマージ後のmainを取り込んでください。

```bash
git fetch origin
git switch main
git pull --ff-only origin main
git switch -c linux/ux-maintenance-check
uv sync --extra dev --extra app
uv run pytest -q
uv run python scripts/build_linux_app.py
```

同名ブランチがあれば新しい作業名を使います。Windows統合ブランチをcherry-pickしたり、
Windowsバイナリを流用したりせず、Ubuntu 24.04 x86_64上で固定のUbuntuエンジン・
7-Zip来歴を使用してネイティブビルドします。他OSのパッケージ処理は変更しません。

## 共通削除修正の注意

`LibraryImportService.delete_managed_storage()`が管理コピー削除エラーを握りつぶし、
ファイルが残ったままDB登録だけ消していた問題を修正しました。削除エラーをDB登録削除より
先に既存の本ごとの失敗通知へ渡します。管理コピーが既にない場合は成功扱いのままです。
失敗した本の登録は残し、他の本の削除成功は反映します。元アーカイブは削除しません。
再帰削除は原子的ではなく、管理コピーが途中まで消える場合があります。
ロック解除後の再試行や、残った元ファイルからの再登録が必要な場合があります。
使い捨てキャッシュの整理は引き続きbest-effortで、削除全体のトランザクション化ではありません。

`test/test_library_removal.py`の失敗・既にない管理コピー・通常削除は全OSで実行します。
実際のファイルロックを使う1件だけはWindows限定です。POSIXでは開いているファイルも
unlinkできるため、Linux/macOSで同じロック失敗を期待しないでください。
共通の失敗条件は権限エラーの模擬テストで確認します。
Windows結果は186成功、9スキップ、5サブテスト成功です。Linuxの結果は別に記録し、
OSによってスキップ数が違うことに注意してください。

## 次のLinux previewまでに実機で確認する8項目

`demo/`の再配布可能な本または生成画像だけを使用します。Ubuntu・デスクトップ・Qtの版、
Wayland/X11、GPU/ドライバ、ソースcommit、ビルド識別名を結果へ残してください。
両セッションを確認できなければ、未確認側を明記します。

1. GNOME WaylandとX11を別々に確認。全画面の画像上で2秒静止するとカーソルが消え、
   マウス／キー操作で戻る。オーバーレイ・メニュー・ダイアログ上やドラッグ中は消えない。
   フォーカスを外して戻した場合も確認する。
2. `F`、`Esc`、読書情報の「本棚へ」でカーソルを復帰し、読書位置を保存する。
   再度開くと保存した位置から再開する。
3. Ctrl+クリック／Shift+クリックの複数選択。選択内の右クリックは選択維持、
   未選択の表紙ならその1冊だけを選択。Waylandと小数倍率でメニュー位置も確認する。
4. デモ2冊を1回の確認で削除し、元ZIPが変わらないことを確認する。
   管理コピーが既にない場合は成功、模擬失敗ならその本の登録維持、他の本は削除成功とする。
5. 対象のPDF／補正キャッシュだけが消え、他の本のキャッシュは残る。
   保存場所はINSTALL.linux.ja.mdのXDGパスを参照し、Mac/Windowsのパスを固定しない。
6. 表示中ページを先に補正し、後方6ページを保持する。遅い読書で前方6へ下がり、
   速く送ると再び増える。判定は中央値なので、1回の待機だけで必ず下がるとは限らない。
7. 補正ONでページ送り後10秒ほど、先読み完了まで目視する。
   補正版→原画→補正版のちらつきがないこと。カラー保持と`O`比較も確認する。
   静止画比較だけで瞬間的なちらつきなしとは判定しない。
8. 全suite・ネイティブ配布物のスモークテスト、パッケージREADMEの
   `packaging/linux/validate-clean-ubuntu.sh`でUbuntu 24.04/26.04を検証する。
   実デスクトップでキャプチャ許可、Alt+C／Alt+U、コントローラ復帰、CBZ順序も再確認する。

`Qt.BlankCursor`が効かなければ環境を記録し、Linux限定の回避を
`src/mangacrisp_app/platform/linux.py`へ置きます。共通`viewer.py`にOS分岐は追加しません。
今回Linuxのキャプチャアダプタ／portal処理は変更していません。
headless CIやコンテナだけではカーソル・キャプチャ・実GPUの実機合格にはなりません。

## 現行previewと停止位置

現行のb0.4 previewは検証済み`main`から公開済みですが、正式版の準備完了を意味しません。未検証のGPU・セッションを
明記し、今後の環境ごとの証跡を記録してから次のpreviewを依頼してください。

b0.4の配布物には次の先行した改善も含まれます。元の検証記録はb0.3のリリース文書を参照してください:

- 全画面のカーソル自動非表示。
- 読書情報オーバーレイの本棚へボタン。
- 本棚の複数選択、右クリックメニュー、まとめて削除。
- 表示中見開きを優先する補正キューと後方6ページ。
- じっくり読む時の前方先読み縮小。
- 修正: 先読み完了時に補正版が原画へ瞬き戻る問題。
- 修正: 管理コピーの削除失敗を通知し、失敗した本の登録を消さない。

英語文案は[English版](linux-handover.md)を使用します。
今後のLinux previewでは、検証済みmainから新しいタグで公開し、checksumを添付します。READMEのダウンロード先は
新しい成果物が実際に利用可能になってから更新してください。
