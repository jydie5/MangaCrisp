## 最初に行うこと

`AGENTS.md`、[並行開発ルール](cross-platform-workflow.md)、
[共通UX引継ぎ](ux-maintenance-handover.ja.md)、
[Linux導入手順](../../INSTALL.linux.ja.md)、

[移植計画](linux-port-plan.ja.md)の古いテスト数や配布方式案より、この引継ぎを優先します。

まず`git status --short --branch`で未コミット変更を確認し、残っていれば保全します。
作業ツリーがきれいになってから、共通修正のマージ後のmainを取り込んでください。

```bash
git fetch origin
git switch main
git pull --ff-only origin main
git switch -c linux/ux-maintenance-check
uv sync --extra dev --extra app
uv run pytest -q
uv run python scripts/build_linux_app.py
```

同名ブランチがあれば新しい作業名を使います。Windows統合ブランチをcherry-pickしたり、
Windowsバイナリを流用したりせず、Ubuntu 24.04 x86_64上で固定のUbuntuエンジン・
7-Zip来歴を使用してネイティブビルドします。他OSのパッケージ処理は変更しません。

## 共通削除修正の注意

`LibraryImportService.delete_managed_storage()`が管理コピー削除エラーを握りつぶし、
ファイルが残ったままDB登録だけ消していた問題を修正しました。削除エラーをDB登録削除より
先に既存の本ごとの失敗通知へ渡します。管理コピーが既にない場合は成功扱いのままです。
失敗した本の登録は残し、他の本の削除成功は反映します。元アーカイブは削除しません。
再帰削除は原子的ではなく、管理コピーが途中まで消える場合があります。
ロック解除後の再試行や、残った元ファイルからの再登録が必要な場合があります。
使い捨てキャッシュの整理は引き続きbest-effortで、削除全体のトランザクション化ではありません。

`test/test_library_removal.py`の失敗・既にない管理コピー・通常削除は全OSで実行します。
実際のファイルロックを使う1件だけはWindows限定です。POSIXでは開いているファイルも
unlinkできるため、Linux/macOSで同じロック失敗を期待しないでください。
共通の失敗条件は権限エラーの模擬テストで確認します。
Windows結果は186成功、9スキップ、5サブテスト成功です。Linuxの結果は別に記録し、
OSによってスキップ数が違うことに注意してください。

## 次のLinux previewまでに実機で確認する8項目

`demo/`の再配布可能な本または生成画像だけを使用します。Ubuntu・デスクトップ・Qtの版、
Wayland/X11、GPU/ドライバ、ソースcommit、ビルド識別名を結果へ残してください。
両セッションを確認できなければ、未確認側を明記します。

1. GNOME WaylandとX11を別々に確認。全画面の画像上で2秒静止するとカーソルが消え、
   マウス／キー操作で戻る。オーバーレイ・メニュー・ダイアログ上やドラッグ中は消えない。
   フォーカスを外して戻した場合も確認する。
2. `F`、`Esc`、読書情報の「本棚へ」でカーソルを復帰し、読書位置を保存する。
   再度開くと保存した位置から再開する。
3. Ctrl+クリック／Shift+クリックの複数選択。選択内の右クリックは選択維持、
   未選択の表紙ならその1冊だけを選択。Waylandと小数倍率でメニュー位置も確認する。
4. デモ2冊を1回の確認で削除し、元ZIPが変わらないことを確認する。
   管理コピーが既にない場合は成功、模擬失敗ならその本の登録維持、他の本は削除成功とする。
5. 対象のPDF／補正キャッシュだけが消え、他の本のキャッシュは残る。
   保存場所はINSTALL.linux.ja.mdのXDGパスを参照し、Mac/Windowsのパスを固定しない。
6. 表示中ページを先に補正し、後方6ページを保持する。遅い読書で前方6へ下がり、
   速く送ると再び増える。判定は中央値なので、1回の待機だけで必ず下がるとは限らない。
7. 補正ONでページ送り後10秒ほど、先読み完了まで目視する。
   補正版→原画→補正版のちらつきがないこと。カラー保持と`O`比較も確認する。
   静止画比較だけで瞬間的なちらつきなしとは判定しない。
8. 全suite・ネイティブ配布物のスモークテスト、パッケージREADMEの
   `packaging/linux/validate-clean-ubuntu.sh`でUbuntu 24.04/26.04を検証する。
   実デスクトップでキャプチャ許可、Alt+C／Alt+U、コントローラ復帰、CBZ順序も再確認する。

`Qt.BlankCursor`が効かなければ環境を記録し、Linux限定の回避を
`src/mangacrisp_app/platform/linux.py`へ置きます。共通`viewer.py`にOS分岐は追加しません。
今回Linuxのキャプチャアダプタ／portal処理は変更していません。
headless CIやコンテナだけではカーソル・キャプチャ・実GPUの実機合格にはなりません。
