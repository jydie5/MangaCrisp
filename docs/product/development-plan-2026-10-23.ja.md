## 1. 結論

次の投資先は、**本棚の検索、ページ移動、しおり管理、読書設定の復元、拡大して読む操作**。
補正と見開きの基盤は既にあり、この5点を整えると日常的な読書の不便を減らせる。

差別化の仮説は「ローカルの漫画を、待たされず、補正の存在を意識せず読めること」。
AI機能の有無だけを独自性とはしない。競合の公式ドキュメントにもAIツールが存在する。
画質や速度で競合を上回るという結論は、同じ入力とハードウェアでの比較前には出さない。

既存の形式追加順 **Comic EPUB → OPDS** は維持する。
まず少数の読書・本棚改善を小さく届け、表示基盤を整え、固定レイアウトEPUBへ進む。
巨大なDB移行、サーバー化、全UI書き直しを小機能の前提にはしない。

### M2: 拡大して読める表示基盤

1. `core/image-viewport` — F07の内部境界だけを分離。通常フィット時は既存と同じ画像・見開き・入力動作。
2. `core/zoom-pan-fit` — ズーム、パン、幅合わせ、実寸、リセット。入力候補は設計時に既存キーと照合する。
3. `core/lazy-page-thumbnails` — F08。独立した小さいサムネイルキャッシュとキャンセル。

**守る条件:**

- ズーム/パンでAIを再実行しない。補正キャッシュのキーと画面表示変換を混同しない。
- 表示用画像がサイズ等に依存する場合だけ、その表示キャッシュ側へ条件を含める。
- パン用ドラッグをページ送りと誤認しない。入力欄のキー・Space/Enterのボタン操作を守る。
- 補正が未完成なら原画で直ちに操作でき、見開きの両側がそろって補正版へ切り替わる。
- 高DPI/複数画面での倍率、読書位置、焦点位置を確認する。
- 新しい操作のキー表示を中央ペインとHヘルプへ同時に反映する。F20全体の完了は前提にしない。
- 1枚の長い見開き画像はまず既存の単ページ表示とズームで扱う。自動分割はM2の対象外として将来評価する。
- デコード済み画像は枚数だけでなく、実バイト量・大画像の一時ピークも測定する。
- サムネイル一覧を開いただけで300ページのPDFを全ページ描画/AI処理しない。

この境界を作ったあとにF19の縦読み、F21/F26の表示変換を追加できる。
これらを全部M2へ含めず、EPUBの予定を際限なく後ろへずらさない。

### M3: 固定レイアウト Comic EPUB — 既存のv0.8.0-beta計画

**M2の全完了は前提ではない。** M0/M1で境界を確認したら、EPUBの仕様spikeはM2と並行して開始する。
表示方式の変更とEPUB adapterは、合意したページソース契約を介して統合する。

1. **spike / 仕様判定**: 直接画像、XHTML内画像、SVG/文字/複合レイアウトの再現方法を比較。
   何を正しく扱い、何を理由付きで拒否するかをfixtureで決定する。
   既存要件はmacOS/Windows中心のため、Linuxを含む初版の対象OSと、依存・来歴・clean package試験を明示する。
2. **ページソース契約**: 現在のPDF/ZIPの境界へ必要なメタデータを足す。
   全形式を一括書き換えせず、既存経路を保ってアダプターを追加する。
3. **EPUB実装**: manifest / spine / cover / RTL / spread指定、コンテナ内URI、遅延画像化。
4. **統合と配布**: 本棚、補正キー、状態保存、全OSの依存・ライセンス・受入。

完了条件: ZIP内ファイル名順でなくspine順。内容・文字・重ね合わせを黙って落とさない。
DRM、リフロー、スクリプト必須、外部取得必須は既存設計どおり対象外。
XXE/DTD、パス逸脱、圧縮爆弾、悪意あるSVG、過大な画素数・展開量を検証する。
新レンダラー/バイナリを加える場合は、固定版・チェックサム・来歴・ライセンスが先。

### M4: 手元の本棚の持続性と整理

- F14～F17を独立PRで実施。軽量export → 読了操作 → メタデータ → 再リンクの順は調整可能。
- 内容指紋を導入しても既存book IDと読書位置/しおりの参照を維持する。
- 重複候補を示し、利用者が別版として残す選択を認める。単純な全件unique制約で強制統合しない。
- 大冊・NAS・外付けでは全ファイルの再ハッシュをUIスレッドで行わない。
- exportは進捗/しおり/設定/メタデータの小さいデータのみ。原本、画像、AIキャッシュを複製しない。
  復元時はスキーマ・入力・パスを検証し、既存内容を即座に上書きしない。
- F18の参照登録前に、移動/欠損/削除の所有権をimport modeとして明文化する。
  参照元の本やフォルダを「本棚から削除」で再帰削除してはならない。

### M5: OPDS 1.2 — 既存のv0.9.0-beta計画

- 最初は検索/ページ分割されたカタログ → 明示ダウンロード → ローカルで読書。
- Komga / Kavita / Calibreの実際の認証とFeedを互換fixtureにする。
- Basic/Digestだけを仮定せず、APIキー付きURLの保存/ログ秘匿も検討する。
- 先に資格情報ストアの共通境界と依存を小さなspikeで確認する。現在のjeepney利用はLinux capture portal用で、
  credential store実装を備えているわけではない。追加依存の配布/ライセンスと、Linuxの未導入・lock・headlessを検証する。
- 秘密はMac Keychain、Windows Credential Manager、LinuxのSecret Service等へ置く。
  利用可能な安全な保管先がない環境の扱いも決め、平文の設定JSONへ逃がさない。
- ネットワークworker、TLS、リダイレクト先への認証情報の持越し制限、タイムアウト、
  サイズ制限、キャンセル、部分ファイルの原子的保存、ダウンロード済み本の再起動後の利用を検証。
- カタログ/本の識別子、診断、exportへ認証用クエリ・パスワード・APIキーをそのまま残さない。
- OPDS v2 / page streaming / server APIによる進捗同期は互換調査を残すが、初版へ混ぜない。

M4の全面実装をOPDSの必須前提にはしない。必要なremote ID・catalog関連だけは既存の設計に沿って追加する。

## 7. 並行作業とリリースゲート

共通の即時ブロッカー・仕様決定・統合は主担当が持つ。
次の作業は所有ファイルが分かれた場合に並行可能:

- 共通UI担当: F03の本棚検索は独立して進められる。F04→F05はreader操作を逐次統合し、F06をAPI確定後に接続する。
- 表示担当: viewportの設計試作。F09統合試験は先に基準を確定するか、viewerの変更点と調整して進める。
  F04/F05、F09、viewportが同じviewerを同時編集しないよう、担当PRと統合順を固定する。
- macOS担当: 同梱エンジン監査、Developer ID/公証、入力/DPI。
- Windows担当: Intel / AMDの固定エンジン証跡、クリーンアカウント、入力/DPI。
- Linux担当: clean Ubuntu検証の自動化、実Wayland/X11、倍率・GPU・portal。

| OS | 未完了作業 | 自動化できる範囲 / 実機に残る範囲 |
| --- | --- | --- |
| macOS | Developer ID署名・notarization、同梱構成のrelease CI | 配布監査・起動は自動化。証明書/アカウントの用意と実際の初回起動は別 |
| Windows | Intel/AMD engine一致、別clean account | 既存の証跡登録・監査を使う。CIの仮想GPUを実GPU合格にしない |
| Linux | 24.04/26.04 clean検証の自動実行、X11/倍率/各GPU | 既存スクリプトの導入/RAR/CPU Vulkan/削除を自動化。物理desktop/portalは別 |

preview公開とstableの合格条件を混同しない。外部機材待ちのゲートは、独立した小機能のpreview開発と並行する。
`core/`、`macos/`、`windows/`、`linux/`、`docs/`のスコープを保ち、配布物は対象OSでビルドする。

## 8. 品質と性能の受入

以下は**新機能で検証する提案**であり、今回測定した値ではない。

- 合成した1万冊メタデータを使い、検索/ソートの応答、選択保持、大量更新を測る。
- 300ページ以上の合法fixtureで最初のページ、ページジャンプ、サムネイルの遅延性を確認する。
- cold/warm補正、前後移動、O/P/F、ウィンドウresize、preset変更、終了を組み合わせる。
- 30分連続読書でメモリ・キャッシュ・GPU/CPU負荷を記録。冊数・ページ数で増え続けないことを確認する。
- 保存容量は既存の各2 GiB/30日方針とactive保護を維持。ズーム/色調整だけでディスクAIキャッシュを増殖させない。
- 8GB級と現在の開発機を区別し、p50/p95と最大メモリを残す。GPUが違う数値を混ぜない。
- 全OS、日英、小画面、倍率差、キーボード/マウス、モーダル/入力欄のフォーカスを確認する。
- fixtureは合成画像か `demo/` の再配布可能素材だけ。個人ライブラリや秘密をテスト/ログへ取り込まない。

## 9. 今すぐには広げない領域

OCR/翻訳、オンライン漫画サイト取得、DRM解除、クラウドの独自同期、モバイル版、
プラグイン市場、大量のAIモデル同梱、アニメーション/音声装飾、完全なUIフレームワーク移行。

将来検討する余地はあるが、依存・費用・各OS保守・ライセンスを伴う。
「競合にあるから」だけで直近の読書改善より上に置かない。
