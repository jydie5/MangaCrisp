# 読書管理の次期改善（2026-10-25）

macOS beta 0.7.1b0.4 / Windows preview 0.7.1b0.6の次の共有機能を検討した記録。
検索・ソート・最近読んだ本・ページジャンプ・しおり・本ごとの設定復元・ズーム・
ページ一覧は実装済み。次巻移動も既にあるため、再実装の対象にしない。

## 競合の公式資料から確認したこと

これは公開された機能の比較であり、速度や使いやすさを実機で比較した結果ではない。
デスクトップアプリとサーバー型アプリでは利用条件が異なる。

| 製品 | 形態 | 参考にする機能と公式資料 |
| --- | --- | --- |
| OpenComic | デスクトップ | [Webtoon・しおり・カスタムキー](https://www.opencomic.app/docs/guides/features/)。[export/restore](https://www.opencomic.app/docs/guides/settings/export-and-restore/)はstorageの手動コピーを案内しており、アプリ内の検証付き復元と同一視しない |
| YACReader | デスクトップ＋Library/Server | [Continue Reading、読了管理、連続スクロール](https://www.yacreader.com/features)、[10.2のDBバックアップ・欠損カバー修復・再スキャン](https://www.yacreader.com/77-lots-of-new-stuff-in-10-2) |
| Komga | サーバー | [未読・読書中・読了と手動変更](https://komga.org/docs/guides/read-progress/)、[方向別の読書モードとWebtoon](https://komga.org/docs/guides/webreader-divina/) |
| Kavita | サーバー | [前後章への移動と縦読み](https://wiki.kavitareader.com/guides/readers/comic-manga/)、[進捗・最終読書日等の絞り込み](https://wiki.kavitareader.com/guides/features/filtering/) |

これらから、まず本棚の読書管理、その次に読書記録の保護、さらに縦読み・キー設定を
進める。サーバー化、多ユーザー認証、外部メタデータの自動取得まで同時に広げない。
従来のComic EPUB → OPDSという形式追加の順序は変えない。

## 実装順と受入条件

1. **F14 読書状態**: 未読・読書中・読了で絞り込み、選択した本を手動で読了/未読へ
   変更する。最終ページへジャンプしただけでは読了にしない。読了後の再閲覧でも
   読了を維持する。未読へ戻すと位置は先頭になるが、しおり・表示設定は残す。
   検索・最近読んだ本と組み合わせ、隠れた選択項目は一括変更対象に含めない。
2. **F15 読書記録の書き出し・復元**: バージョン付きJSONに読書位置・しおり・本ごとの
   表示設定を保存する。原本、管理コピー、AIキャッシュ、認証情報を含めない。
   初版は同じ本棚の既存IDに一致する本だけを復元し、別PCの再取り込みや名前だけの
   自動照合は対象外とする。全体検証・変更内容確認・トランザクションが必要。
3. **F17 欠損本の再リンク**: 既存IDを保ち、利用者が確認した候補へ接続する。
   同名だけで統合・削除しない。内容指紋は照合補助として別途設計する。
4. **F19 縦読み**: 可変高さと表示周辺の仮想化を先に設計する。全ページ画像の展開や
   補正キュー投入をしない。ページ内位置の保存、メモリ計測、入力の競合を評価する。
5. **F20 キー設定**: 共通action定義から操作・中央ペイン・Hヘルプを生成する。
   競合検出・OSごとの表記・既定値復元をそろえてから編集UIを追加する。

## 配布と検証の境界

新機能は共有コードの独立PRで扱い、公開中の配布物を上書きしない。
テストは合成データまたは再配布可能なdemoを使う。共有suiteと各OSのCI、
画面の見切れ・キーボード操作・実機での受入を区別して記録する。
未完成EPUBや他OSの包装変更をこの機能へ混ぜない。
