# 連番スクリーンキャプチャ機能：検討事項と初期構成

更新日: 2026-08-12

状態: 初期検討資料。初版の実装候補仕様は
[連番スクリーンキャプチャ初版 要件定義・設計](sequential-screen-capture-v1.ja.md)へ分離した。

## 目的

MangaCrispで読める画像アーカイブを、利用者が自分で表示している画面から
作成できるようにする。初期案は特定の電子書籍サービスを解析・抽出する機能ではなく、
Windowsの `Win + Shift + S` やmacOSのスクリーンショットに近い、汎用の
連番スクリーンキャプチャ機能とする。

想定する基本操作は次のとおり。

1. 利用者が保存先とキャプチャ対象（画面、ウィンドウ、固定範囲）を選ぶ。
2. 利用者が対象アプリでページを表示する。
3. グローバルショートカットを押す。
4. `000001.png`、`000002.png` のように連番で保存する。
5. 利用者自身がページを送り、必要な回数だけ撮影を繰り返す。
6. 撮影結果を確認・修正してZIPまたはCBZへまとめる。

## 現時点の法務・規約上の整理

この項目は法的助言ではなく、日本の公開一次資料を基にした開発上の境界整理である。

日本の著作権法第30条では、家庭内などの限られた範囲で、仕事以外の目的に使用し、
使用する本人が複製する場合に「私的使用のための複製」が認められる。ただし、
コピーガードを解除して行う複製などは対象外となる。文化庁の解説には、私的複製の
可否を1ページ、1冊といった数量だけで区切る基準は示されていない。

そのため、正規に閲覧できる画面を、OSの通常のスクリーンキャプチャ機能で、本人が
自分または家庭内だけで読むために保存する行為は、私的複製に該当する余地がある。
ただし、次の点から「電子書籍1冊の保存が常に適法」と保証することはできない。

- DRM解除、キャプチャ禁止機能の無効化、黒画面回避などを行うと、私的複製の例外から
  外れる可能性が高い。
- 著作権法上の私的複製に該当しても、電子書店との利用契約に反する可能性がある。
- BOOK☆WALKERやコミックシーモアなど、複製を明示的に禁止しているサービスがある。
- Kindleの公開日本語EULAでも、コンテンツ保護機能の迂回、修正、無効化、回避を
  禁止している。ただし、公開PDFの最終更新日は2011年であり、実際の利用時には
  購入画面やアカウントに表示される最新規約も確認する必要がある。
- スクリーンショット画像をSNS等へ投稿する行為は私的使用ではない。1ページだけ、
  または多くの人が行っているという理由だけで適法になるわけではない。引用として
  利用する場合は、必要性、明瞭な区別、主従関係、出典表示などを個別に満たす必要がある。

MangaCrispでは、利用者が権利または許諾を持つ素材、自作素材、パブリックドメイン、
ライセンス条件を満たす素材、DRMフリー素材で利用できる汎用機能として設計する。
特定の商用電子書籍サービスから全冊を取得することを製品目的や宣伝文句にしない。

## 初期リリースに含める範囲

### キャプチャセッション

- セッション名と保存先を指定する。
- 画面全体、アプリのウィンドウ、固定矩形範囲から選択する。
- 撮影範囲と出力サイズをセッション中は固定できる。
- 保存先には新しいセッションフォルダを作り、既存ファイルを上書きしない。
- 連番の開始値は通常 `1` とし、既存番号がある場合は次の空き番号を使う。

### 撮影操作

- 利用者が設定可能なグローバルショートカットで1枚ずつ撮影する。
- 撮影成功時は、小さなプレビュー、現在の番号、保存成功を短時間表示する。
- 直前の撮影を取り消し、同じ番号で撮り直せる。
- 二重入力を防ぐ短いデバウンスを設ける。
- ページ送りは利用者が対象アプリで手動で行う。

### 撮影結果の確認

- サムネイル一覧を表示する。
- 順番の入れ替え、削除、撮り直しを行える。
- 完全一致または知覚ハッシュによる重複候補を表示する。
- 真っ黒、透明、極端に小さい画像は失敗候補として警告する。
- 警告された画像を自動的に補正・回避して取得し直すことはしない。

### 出力

- 初期保存形式はPNGとする。JPEGは後続評価とする。
- ファイル名は6桁のゼロ埋め連番とする。
- ZIPとCBZは同じ内容を持ち、利用者が拡張子を選択できる。
- アーカイブ内のページ順はファイル名順で確定する。
- 出力前に最終ページ数と先頭・末尾のサムネイルを確認する。

出力例:

```text
CaptureSession/
  pages/
    000001.png
    000002.png
    000003.png
  manifest.json
  CaptureSession.cbz
```

`manifest.json` には、少なくとも次を保存する。

- 形式バージョン
- セッション作成日時
- 撮影方式（画面、ウィンドウ、固定範囲）
- 出力画像の寸法
- ページ番号、ファイル名、SHA-256
- 削除・撮り直しを反映した最終ページ数

対象アプリ名、書名、ローカルの絶対パスなど、不要な個人情報はアーカイブへ入れない。

## 初期リリースに含めない範囲

- Kindleなど、特定サービス専用の取得モード
- 対象アプリの自動ページ送り
- 無人での全ページ取得
- DRMの解除、復号、鍵の取得
- 対象プロセスへのコード注入、メモリ読み出し、内部画像の抽出
- OSやアプリが拒否したキャプチャの回避
- 黒画面を別経路から取得する機能
- 透かし、著作権表示、権利管理情報の除去
- 自動アップロード、共有、公開

これらは「技術的に可能か」ではなく、MangaCrispの初期機能として意図的に扱わない。

## 共通コードとOS固有コードの境界案

共通部分には、セッション、採番、メタデータ、重複検出、レビュー、ZIP/CBZ生成を置く。
画面取得、権限確認、グローバルショートカット登録だけをOS固有アダプターへ分離する。

```text
src/mangacrisp_app/
  capture/
    session.py
    manifest.py
    review.py
    package.py
  platform/
    capture_common.py
    capture_macos.py
    capture_windows.py
```

実際の配置は既存モジュールとの依存関係を確認して決定する。共通APIを先に
`core/<topic>`ブランチで確定し、macOSとWindowsのキャプチャ実装をそれぞれ
`macos/<topic>`、`windows/<topic>`へ分ける。

OS固有アダプターに必要な最小API案:

```python
class ScreenCaptureBackend:
    def request_permission(self) -> bool: ...
    def list_capture_targets(self) -> list[CaptureTarget]: ...
    def capture(self, target: CaptureTarget, region: Rect | None) -> CapturedFrame: ...
    def register_hotkey(self, shortcut: Shortcut, callback) -> None: ...
    def unregister_hotkey(self) -> None: ...
```

macOS側では、初回の画面収録権限、権限拒否後の案内、Retinaスケール、複数ディスプレイ、
フルスクリーンアプリ、MangaCrisp自身のプレビューを撮影対象から除外できるかを確認する。

## ヒューマンチェックの最初のゴール

権利上問題のないデモ画像または自作画像だけを使い、Mac実機で次を確認した時点で停止し、
利用者へチェックを依頼する。

1. 画面収録権限を案内できる。
2. 対象ウィンドウまたは固定範囲を選択できる。
3. 対象アプリをフルスクリーンにしてもホットキーが動作する。
4. 10ページを `000001.png` から `000010.png` として欠番なく保存できる。
5. 直前の1枚を取り消して撮り直せる。
6. 同じ画面を2回撮った場合に重複候補が表示される。
7. 撮影した10ページをCBZへまとめ、MangaCrispで正しい順番に開ける。
8. OSがキャプチャを拒否した場合、回避せずに停止して理由を案内する。

このヒューマンチェックを通過するまでは、自動ページ送りや大量撮影の最適化へ進まない。

## Mac側と決めたい事項

- 機能をMangaCrisp本体へ統合するか、別の小さな「Capture」ウィンドウにするか。
- 初期ショートカットと、既存アプリとの衝突時の変更方法。
- 画面全体、ウィンドウ、固定範囲のどれを初期選択にするか。
- 撮影成功通知を音、オーバーレイ、両方のどれにするか。
- 一時ページ画像と完成CBZの削除・保持方針。
- 左右見開きを1画像のまま保存するか、任意分割機能を後から追加するか。
