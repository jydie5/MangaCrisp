## F17: 欠損検出と再リンク

### 現在の制約

- `library.local_content_id()`はパス、サイズ、更新時刻、一部内容ハッシュを使う。
  移動した本を再登録しても同じIDになるとは限らない。
- 読書位置・しおりはbook IDと物理ページ番号に結び付く。再リンクに
  `register_local_book()`、`import_local_books()`、scanner結果のupsertを使わない。
- archiveを管理領域へ取り込むと`file_kind`がfolderになる。PDFも管理コピーと
  外部参照で同じkindを使う。kindだけで所有権を判断できない。
- 元archiveがなくても、管理コピーの`local_path`が読めれば欠損ではない。
- DBは旧ページ順・ページ名・ページハッシュのmanifestを持たない。
  **ページ数一致は同じ内容・同じ順序の証明にならない。**

### PR A: 欠損状態の表示だけ

`BookshelfWindow.reload_books()`のスナップショット更新後、別workerで各`local_path`の
存在と種類を一度確認する。画像列挙、archive展開、PDF描画は行わない。
結果を世代番号付きavailability mapとしてUIへ戻し、古いreloadの結果は捨てる。
検索・進捗フィルター・ソートではmapを参照し、追加のファイルI/Oをしない。

検査中、利用可能、見つからない、アクセス不能を区別する。NAS等のI/O待ちでUIを
停止させず、終了時にworkerを待ち続けない。threadの取消フラグではブロック中の
OS I/Oを止められないため、timeoutを必要とする経路はprocess分離等も評価する。アクセス不能を自動削除の根拠にしない。
`open_book()`でも単体を再確認し、検査後に消えたケースを通常のエラーとして扱う。
管理コピー欠損時に元archiveを黙って開いたり、再取り込みしたりしない。

受入: reload単位の検査回数、検索中の追加I/Oなし、遅い/アクセス不能なsource、
reload世代切替、open直前の欠損、終了処理を合成fixtureで検証する。

### PR B: 外部参照の明示再リンク

初版は欠損した単画像または画像フォルダだけを対象にする。
`managed_book_dir_from_book(book, library_dir) is None`を満たすものだけ許可する。
この判定も保存先に基づく推定なので、library配下に直接登録したfolder等は
安全側で対象外にする。将来`storage_mode`等を導入して判定を明示化する。

1. ユーザーが選んだ候補を`BookScanner`で一度検査する。元のkindと候補の種類、
   ページ数、読書位置と全しおりの番号が範囲内かを確認する。
2. 候補folderは`collect_folder_images()`による既存の自然順を使う。
   旧順は照合できないため、確認画面で「ページ番号ベースの位置・しおりを維持するが、
   同じ場面を指すかは確認が必要」と明示する。ページ数一致だけで自動承認しない。
3. 旧/新パス、件数、影響、順序照合の制限を見せ、取消を既定にする。
4. 確認時に対象bookの旧値と候補の検査結果がまだ有効かを再確認し、transaction内の
   targeted UPDATEで同じbook IDのsource情報だけ変更する。stale previewは再確認へ戻す。
5. しおり、読書位置、表示設定、読了状態、作成日時は変更しない。
   検査やDB更新に失敗したら更新を残さず、元ファイルを移動・削除しない。

再リンクそのものではキャッシュを削除しない。新source identityを使うことを検証し、
旧キャッシュは通常の保持期限で処理する。削除処理は外部原本を消さないことを
別途テストする。既存ID由来の管理領域が残る場合も、外部候補へ削除範囲を広げない。

受入: 同一IDと全読書記録の維持、種類/ページ数/範囲不一致の拒否、取消、
DB失敗rollback、確認中の変更検知、順序未照合の表示、再リンク後の外部原本保護。
「同じ枚数で順番が違う候補を検知できる」というテスト/仕様は置かない。

### 後続へ分離

archive/PDFの再リンク、管理コピー修復、内容指紋による候補提示は別PRとする。
archive内の巻分割・順序・staging repairを設計してから扱う。
自動統合/削除、タイトルだけの照合は行わない。ページmanifestの導入は移行方法と
旧本の未検証状態を設計し、既存データを読み取れる状態を維持する。

## F19: 縦スクロール読書

最初のPRはQtから独立したレイアウト計算と合成ページの検証に限定する。
`image_viewport.py`の座標処理、`page_provider.py`の遅延materializeとidentity、
`page_thumbnails.py`の可視範囲要求を参照するが、ページ一覧をそのまま読書面へ転用しない。

- ページ高の累積値から可視範囲を求め、表示範囲と小さな前後余白だけdecode/補正する。
  未知の縦横比には仮寸法を使い、判明後は現在のページとページ内位置をanchorに保つ。
- metadata取得のためだけに全PDF/ZIPページを描画・展開しない。1万ページの合成sourceで
  materialize数、要求キュー、表示キャッシュがページ総数に比例して増えないことを確認する。
- resize、全画面、画質切替、補正画像への置換で読んでいる位置を飛ばさない。
- 縦読み時の保存位置は物理ページ番号とページ内の相対位置が必要。DB移行、既定値、
  読書記録JSONのversion互換性を別PRで設計してから永続化する。
- 通常スクロールとCtrl/Meta+wheelのズーム、タッチパッド慣性、ドラッグ、中央ペイン、
  Shift+カーソルの意味を先に決める。見開き読書の既存操作を壊さない。

次にfeature flag下の読書面を加え、画像folder→PDF/ZIPの順に比較する。
リリース判断には10分読書のメモリ/キャッシュ計測と3OSの入力確認を使う。
性能の数値目標はbaseline計測後に決め、未計測値を保証値として公開しない。

## F20: ユーザーのキー割当

#79は組み込みaction共通化の第一段階。keycap、binding、グループ化されたhelpには
まだ個別の定義があるため、そのまま設定UIを足すと表示と動作がずれる。

1. 有効なbinding集合からキー表示を生成する層を先に作る。action IDを安定キーとし、
   日本語/英語の文面、物理キー、修飾キー、RTL/LTRでの意味を分離する。
2. 既定値＋利用者overrideを検証し、同一context内の衝突、予約キー、未知action、
   不正な設定を扱う。保存は原子的に行い、既定値へ戻す導線を常に残す。
3. Esc、テキスト入力、IME、ダイアログ、メニューの優先順位を保つ。
   キャプチャのグローバルキーとは別contextにし、OS予約キーは上書きしない。
4. 設定UIは最後に追加する。編集したキーがdispatch・中央ペイン・Hヘルプに同時反映され、
   再起動後も一致することを受入条件にする。Shift表記、+/=、?、テンキーとOS差も検証する。

Comic EPUBとOPDSの順序は変更しない。未完成EPUBはこの候補へ取り込まない。
