## 1. 初版で確定する方針

| 項目 | 初版の決定 |
|---|---|
| 提供形態 | MangaCrisp本棚から起動する、独立した小型Captureコントローラ |
| 最初の対象OS | macOS Apple Silicon。共有部分はWindowsで再利用可能にする |
| 必須の取得対象 | 利用者がドラッグ指定した固定矩形範囲 |
| 追加候補 | 画面全体。ウィンドウ単位取得は初版後 |
| ページ送り | 利用者が対象アプリで手動操作 |
| 撮影 | 利用者が変更可能なグローバルショートカットで1枚ずつ実行 |
| 画像形式 | PNG。画面のカラーを保持し、AI補正や減色を行わない |
| 完成形式 | CBZを既定、ZIPを選択可能 |
| 撮影通知 | 対象範囲と重ならない小型表示。音は任意で既定OFF |
| 元PNG | 完成後も保持。利用者が明示した場合だけ削除 |
| 見開き分割 | 初版では行わず、画面に見えた1回分を1画像として保存 |
| 自動化 | 自動ページ送り、無人撮影、キャプチャ拒否回避は行わない |

Captureコントローラを本棚・リーダーと同じ画面へ埋め込まない。対象アプリを操作しながら
状態を確認する用途のため、移動可能で最小化できる別ウィンドウとする。ただし入口、設定、
セッション履歴はMangaCrisp本体が管理し、別製品にはしない。

## 2. 利用者価値

- 自作、許諾済み、パブリックドメイン、DRMフリーなど、利用者が保存する権利を持つ
  画面素材を連番画像へまとめられる。
- OSの単発スクリーンショットを繰り返して手作業で改名する必要がない。
- 欠番、重複、黒画像を完成前に確認できる。
- 作成したCBZをそのままMangaCrisp本棚へ登録して読める。

## 3. 対象外

- 特定電子書籍サービス専用モード
- DRM、暗号化、画面保護、黒画面の解除または回避
- 対象プロセスへのコード注入、メモリ・内部画像・通信内容の取得
- 自動ページ送り、連写、タイマーによる無人全ページ取得
- 透かし、権利表示、著作権管理情報の削除
- クラウド同期、共有、公開、OCR、PDF化
- JPEG、WebP、AVIF出力
- 見開きの自動分割、余白除去、傾き補正

## 4. 基本フロー

### 4.1 セッション作成

1. 本棚のツール領域からカメラアイコンの「Capture」を開く。
2. セッション名、保存先、撮影ショートカットを確認する。
3. 「範囲を選択」を押し、対象ディスプレイ上をドラッグする。
4. 選択範囲の物理ピクセル寸法と保存先を確認する。
5. macOSの画面収録権限がなければ、理由とシステム設定への案内を表示する。
6. 「撮影を開始」を押して待機状態へ移る。

既定ショートカット候補は `Command+Option+C`、直前取消は
`Command+Option+Z` とする。登録失敗または既存アプリとの衝突時は撮影を開始せず、
利用者に別の組み合わせを選ばせる。ショートカットは設定へ保存する。

### 4.2 撮影

1. 利用者が対象アプリでページを表示する。
2. 撮影ショートカットを押す。
3. 現在の固定範囲を1回だけ取得する。
4. 一時ファイルへPNGを書き、完了後に `000001.png` へ原子的に置き換える。
5. 保存完了後に番号、サムネイル、警告の有無を通知する。
6. 利用者が対象アプリでページを送り、必要な回数だけ繰り返す。

入力デバウンスは150msを初期値とする。保存処理中に次の入力が来た場合は最大2件まで
順番を保持し、それを超えた入力は保存せず警告する。黙って欠番を作らない。

### 4.3 取消と撮り直し

- 「直前取消」は最後に確定したページだけを対象にする。
- 取り消したファイルはセッション内の一時退避領域へ移し、次回撮影で同じ番号を使う。
- 取消後に別ページを編集した場合、単純なUndo履歴は終了する。
- 任意ページの撮り直しはレビュー画面で番号を選び、次の1回だけその番号へ置換する。

### 4.4 レビューと出力

- サムネイルを番号順に表示する。
- ドラッグで順番を変更し、削除、撮り直し、回転を行える。
- 完全一致、近似重複、黒・透明・極小画像を警告する。自動削除はしない。
- 出力前にページ数、先頭、末尾、警告件数、出力先を確認する。
- CBZ/ZIPは一時ファイルへ生成し、検証後に完成名へ原子的に置き換える。
- 完成後に「MangaCrisp本棚へ追加」を選べる。自動登録はしない。

## 5. 機能要件

| ID | 要件 | 優先度 |
|---|---|---|
| CAP-001 | 新規セッションごとに衝突しない専用フォルダを作る | 必須 |
| CAP-002 | 固定矩形範囲を再利用できる | 必須 |
| CAP-003 | Retinaと複数ディスプレイで論理座標を物理ピクセルへ正しく変換する | 必須 |
| CAP-004 | 対象アプリが前面でもグローバルショートカットが動く | 必須 |
| CAP-005 | 1入力につきPNGを1枚だけ保存する | 必須 |
| CAP-006 | 6桁連番を使い、既存ファイルを上書きしない | 必須 |
| CAP-007 | 直前取消と同番号での撮り直しができる | 必須 |
| CAP-008 | 順番変更、削除、任意ページ撮り直しができる | 必須 |
| CAP-009 | SHA-256完全一致を検出する | 必須 |
| CAP-010 | 知覚ハッシュによる近似重複候補を表示する | 推奨 |
| CAP-011 | 黒、透明、極小の失敗候補を警告する | 必須 |
| CAP-012 | CBZまたはZIPを自然順で生成する | 必須 |
| CAP-013 | 生成物を既存本棚インポートへ渡せる | 必須 |
| CAP-014 | 権限拒否、対象消失、ディスク不足から安全に停止できる | 必須 |
| CAP-015 | アプリ終了後に未完了セッションを復元できる | 必須 |
| CAP-016 | 画面全体を固定範囲の特殊ケースとして取得する | 任意 |

## 6. 非機能要件

### 性能

- ホットキー入力から撮影開始まで100ms以内を目標とする。
- 1枚の保存完了通知は通常300ms以内を目標とする。
- UIスレッドでPNG圧縮、ハッシュ計算、CBZ生成を行わない。
- メモリ上に保持する未保存フレームは最大3枚とする。
- 10ページ連続操作で欠番、重複採番、UI停止を発生させない。

### 信頼性

- PNGとアーカイブは一時ファイルからの原子的置換で確定する。
- `manifest.json` は画像確定後に更新し、クラッシュ時は実ファイルから再構築できる。
- ページ削除や並べ替えで元PNGを即座に破壊せず、完成アーカイブの順序を別管理する。
- ディスク空き容量が想定2ページ分を下回ったら新規撮影を停止する。

### プライバシー

- 画像、セッション情報、診断情報をネットワークへ送信しない。
- マニフェストに対象アプリ名、ウィンドウタイトル、絶対パス、ユーザー名を保存しない。
- 診断情報へ画像ハッシュやセッション名を含めない。

### アクセシビリティ・言語

- すべての操作はボタンでも実行でき、ショートカットだけに依存しない。
- 色だけで成功・警告・失敗を区別しない。
- 日本語と英語を同時に実装する。
- アイコンボタンにはツールチップとアクセシブル名を付ける。

## 7. データ設計

```text
<利用者が選んだ保存先>/
  <safe-session-name>-capture-<YYYYMMDD-HHMMSS>/
    pages/
      000001.png
      000002.png
    .undo/
    manifest.json
    <safe-session-name>.cbz
```

`manifest.json` の形式バージョンは `1` とする。

```json
{
  "schema_version": 1,
  "created_at": "2026-08-12T12:34:56Z",
  "capture_mode": "fixed_region",
  "pixel_size": {"width": 1800, "height": 2700},
  "pages": [
    {
      "position": 1,
      "file": "pages/000001.png",
      "sha256": "...",
      "perceptual_hash": "...",
      "warnings": []
    }
  ],
  "output": {"format": "cbz", "file": "book.cbz"}
}
```

セッション名はフォルダ名と出力名に使える文字へ正規化する。アーカイブ内には
`pages/000001.png` ではなく `000001.png` のように画像だけを格納し、
`manifest.json` は初版ではアーカイブへ含めない。

## 8. ソフトウェア設計

### 8.1 モジュール境界

```text
src/mangacrisp_app/
  capture/
    models.py          # セッション、ページ、警告、状態
    session.py         # 採番、保存、取消、復旧
    coordinator.py     # 状態遷移とバックエンド調停
    validation.py      # ハッシュ、黒・透明・寸法検査
    package.py         # CBZ/ZIP生成と検証
    review_model.py    # 並べ替え、削除、撮り直し指定
  capture_window.py    # 小型コントローラとレビュー画面
  region_selector.py   # 複数画面対応の範囲選択UI
  platform/
    capture_base.py    # 共通Protocolとデータ型
    capture_macos.py   # 権限、画面取得、グローバルホットキー
    capture_windows.py # Windows実装時に追加
```

本棚にはCapture起動コマンドだけを追加する。読書キャッシュ、Real-CUGAN、PDFレンダラー、
本棚DBをキャプチャ処理へ依存させない。

### 8.2 バックエンド契約

```python
class ScreenCaptureBackend(Protocol):
    def permission_state(self) -> PermissionState: ...
    def request_permission(self) -> PermissionState: ...
    def list_displays(self) -> list[CaptureDisplay]: ...
    def capture_region(self, region: PhysicalRect) -> CapturedFrame: ...
    def register_hotkeys(self, bindings: HotkeyBindings, callback: Callable) -> None: ...
    def unregister_hotkeys(self) -> None: ...
```

`CapturedFrame` は物理ピクセル寸法、RGBA/BGRA画像データ、取得時刻だけを返す。
対象アプリ名やウィンドウタイトルは共通層へ渡さない。

### 8.3 状態遷移

```text
IDLE -> CONFIGURING -> PERMISSION_REQUIRED -> READY
READY -> CAPTURING -> SAVING -> READY
READY -> REVIEWING -> PACKAGING -> COMPLETE
CAPTURING/SAVING/PACKAGING -> ERROR -> READY or REVIEWING
```

CaptureとSaveは1本の順序付きキューで処理する。UI更新はSignalでQtメインスレッドへ戻す。
終了時、権限変更時、スリープ時には必ずグローバルホットキーを解除する。

### 8.4 macOS取得方式の実証結果

実装開始時に、macOS公開APIを使う2方式を小さなプロトタイプで比較する。

1. ScreenCaptureKitをPythonバインディングまたは小型ネイティブhelperから利用する。
2. Qtの画面取得を固定範囲用途に利用する。

採用条件:

- Retinaの物理ピクセル寸法が一致する
- 複数ディスプレイとフルスクリーンアプリで動く
- 権限拒否を判定できる
- MangaCrispの配布アプリへライセンス込みで同梱できる
- グローバルホットキーに汎用キーロガー権限を要求しない
- 10回連続で欠番なく撮影できる

2026-08-12の初版実装では、追加依存を増やさずQt `QScreen.grabWindow` とmacOS公開APIを
採用した。M4 Pro内蔵ディスプレイで、論理解像度ではなく `3456x2234` の画面寸法、カラー
RGBA取得、画面収録権限判定を確認した。グローバルショートカットはCarbon
`RegisterEventHotKey` を利用し、入力監視・アクセシビリティ権限を要求しない。

ScreenCaptureKitは、Qt方式で複数ディスプレイ、別Space、フルスクリーン対象に不具合が
確認された場合の次候補とする。初版へネイティブhelperや追加パッケージは同梱しない。

## 9. エラーと利用者への表示

| 状況 | 動作 |
|---|---|
| 画面収録権限なし | 撮影開始を拒否し、システム設定への案内を表示 |
| 権限が途中で失効 | セッションを保存して停止。再許可後に再開可能 |
| 範囲が画面外 | 再選択を要求。自動で別範囲へ変更しない |
| 対象画面が切断 | 撮影停止。保存済みページは維持 |
| 黒・透明画像 | 保存した上で警告。回避撮影はしない |
| ショートカット競合 | 待機開始を拒否し、変更画面を表示 |
| 保存失敗・容量不足 | 番号を消費せず停止し、再試行可能にする |
| CBZ生成失敗 | 元PNGとセッションを維持する |

## 10. テスト設計

### 自動テスト

- 採番、既存番号回避、取消、同番号撮り直し
- セッション名の安全化と保存先逸脱防止
- 一時ファイルからの原子的確定
- マニフェスト保存、クラッシュ後復旧、未知スキーマ拒否
- 完全一致・近似重複と失敗候補判定
- 並べ替え・削除後のCBZ自然順とCRC検証
- 画像以外をCBZへ混入しないこと
- Fake backendによる状態遷移、連打、権限失効、ディスクエラー
- 診断情報へ個人情報が入らないこと
- 日本語・英語UIテスト

### macOS統合テスト

- 画面収録権限の未決定、許可、拒否
- Retina 1画面と倍率の異なる複数画面
- 対象アプリが前面、フルスクリーン、別Spaceにある場合
- スリープ・復帰、画面切断、アプリ終了時のホットキー解除
- 配布 `.app` でPython/uvなしに動作すること
- 新規依存関係、helper、権限説明文、ライセンスの配布監査

## 11. 初回ヒューマンチェック

権利上問題のない `demo/` 素材または自作画像だけを使う。

1. 本棚からCaptureコントローラを開ける。
2. 権限案内からmacOS設定へ移動し、再起動または再試行できる。
3. 固定範囲を選び、物理ピクセル寸法を確認できる。
4. 対象アプリをフルスクリーンにしてもショートカットが動く。
5. 10ページを `000001.png` から `000010.png` まで欠番なく保存できる。
6. 直前取消後、同じ番号で撮り直せる。
7. 同じ画面を撮ると重複候補が表示される。
8. 黒画像を渡すFake/テスト経路で警告し、回避しない。
9. 並べ替えた10ページをCBZへ出力し、MangaCrispで同じ順に読める。
10. 完成後も元PNGが残り、明示削除した場合だけ消える。

ここまで通過した時点で利用者へ確認を依頼する。ウィンドウ単位取得、見開き分割、
JPEG出力などへ進むのは、その評価後とする。

## 12. 実装順

1. `core/capture-session` でモデル、採番、保存、復旧、検証、CBZ生成をTDD実装
2. `macos/capture-spike` で取得API、権限、Retina、ホットキー、配布を実証
3. 採用方式を記録して `macos/capture-backend` を実装
4. `core/capture-ui` でコントローラ、範囲選択、レビューを実装
5. 本棚入口と本棚登録を結合
6. 配布監査、自動テスト、Mac実機ヒューマンチェック

共有APIを先にmainへ入れ、macOSとWindowsが同じファイルを同時に変更しない。
